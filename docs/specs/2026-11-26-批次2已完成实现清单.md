## 第 1 步：上传、落盘、拒绝、状态

1. 登录后对当前知识空间 `POST /api/spaces/{space_id}/documents`，multipart 字段名 `file`。
2. 按扩展名判定 `kind`：`.pdf` → pdf，`.docx` → docx，`.md` / `.markdown` → markdown。其它类型（含 xlsx / pptx / 旧 `.doc`）返回 400，文案固定「只接受 PDF、Word、Markdown」。空文件同样拒绝。
3. 原文件写到 `data/originals/{space_id}/{doc_id}/{filename}`，`documents.stored_path` 记相对路径，创建后不改。
4. 行写入后 `status=processing`，立刻返回列表项；建库不堵在上传请求里。
5. PDF / Word 在接受上传前先 `GET` 本机 MinerU `v1/health`（8001）。连不上则 503，不收下文件。Markdown 跳过这一步。
6. 禁止 `pypdf` / `python-docx` 抽文本；`pyproject.toml` 已去掉这两个依赖。禁止 mineru.net 和把 MinerU 装进本仓库 uv 环境。

主要代码：`api/app/storage/originals.py`、`api/app/services/documents.py`、`api/app/routes/documents.py`。

---

## 第 2 步：后台调本机 MinerU，再进 LightRAG

1. 上传返回后 `ingest.schedule(doc_id)` 丢到当前事件循环，后台跑完再改状态。
2. 建库过程中**不占用**上传用的数据库会话：读完原文件就关会话，MinerU / LLM 期间不占连接。
3. **Markdown**：UTF-8 解码后整篇 `ainsert`，`file_path` 就是文件名（没有页）。
4. **PDF / Word**：HTTP 调本机 `mineru-kit api-server`（`MINERU_API_URL`，默认 `http://127.0.0.1:8001`）Tasks API：建任务 → PUT 原文件 → 轮询 → 下 ZIP。
5. ZIP 里取 `markdown.md` 和 `structured_content.json`。空结果、缺文件、JSON 坏了，都记失败。
6. 进 LightRAG 的只是各页的 **Markdown 文本**（从 JSON 的 `pages[].blocks[].content` 拼出来），调用 `ainsert(texts, file_paths=...)`。
7. **`structured_content.json` 整份 JSON 不进 LightRAG**，不当 chunk。
8. 成功：`status=ready`。失败：`status=failed`，`error_msg` 给人看（MinerU 连不上、解析空、模型未配置等），该文档不进入检索。
9. 配置：`.env` 的 `MINERU_API_URL` / `MINERU_TIER` / `MINERU_OCR_MODE`（数字 PDF 默认 `flash` + `txt`）。HTTP 客户端是 `httpx`。

主要代码：`api/app/parse/mineru.py`、`api/app/services/ingest.py`、`api/app/lightrag/engine.py`。

## 第 3 步：工作台文档栏

1. 右栏「文档」只列**当前知识空间**的文档；切空间后列表跟着换。
2. 每条显示文件名 + 状态文案：**处理中** / **已就绪** / **失败**。失败额外显示 `error_msg`。
3. 存在处理中文档时每 2 秒轮询列表，直到变为已就绪或失败。
4. 「上传」按钮上传中显示「上传中」并禁用，避免连点。前端先按扩展名拦一刀，与后台同一句拒绝文案。
5. 「打开原文」走同源 `GET /api/spaces/{space_id}/documents/{doc_id}/original`，`Content-Disposition: inline`，浏览器打开的是 **data/originals 里的原文件**（PDF / Word / Markdown），不是 `markdown.md` 解析稿。
6. 不用 blob URL 打开：blob 会丢掉 `#page=n`，PDF 以后无法落到页。
7. 「删除」只删产品表行和磁盘上的原文件、解析稿；图谱侧清理留给批次 4。删除中按钮显示「删除中」。
8. 无空间时空状态「先创建一个知识空间」；有空间无文档「还没有文档」。

主要代码：`web/src/pages/workbench/Documents.tsx`、`web/src/api/documents.ts`。

## 第 4 步：页锚点（不挡主路径）

1. MinerU `page_idx` 是 0 起；插入 LightRAG 时写成 `制度.pdf#page=12`（1 起）。
2. 每一页一段 Markdown 文本，对应一个 `file_path`。空页跳过。
3. `structured_content.json` 和 `markdown.md` 落到 `data/parses/{space_id}/{doc_id}/`，只给产品自己用（以后点来源对页）。删文档、删空间时一起清掉。
4. 前端 `originalUrl(spaceId, docId, page)` 会拼 `/original#page=n`；`splitPageAnchor` 能从 LightRAG 的 `file_path` 拆出文件名和页码。文档栏「打开原文」暂不带页；问答点来源带页留给批次 3。
5. 后端 `split_page_anchor` 在 `api/app/parse/page_anchor.py`，同一套规则。

主要代码：`api/app/parse/mineru.py` 的 `pages_from_structured`、`api/app/storage/parses.py`、`web/src/api/documents.ts`。

## 接口（批次 2 产品用）

| 方法 | 路径 | 行为 |
|---|---|---|
| GET | `/api/spaces/{space_id}/documents` | 当前空间文档列表 |
| POST | `/api/spaces/{space_id}/documents` | 上传，返回 `processing` |
| GET | `/api/spaces/{space_id}/documents/{doc_id}/original` | 原文件，inline |
| DELETE | `/api/spaces/{space_id}/documents/{doc_id}` | 删产品记录和磁盘文件 |

列表项字段：`id`、`filename`、`kind`、`status`、`error_msg`、`created_at`。

## 磁盘约定

| 路径 | 内容 | 进 LightRAG？ |
|---|---|---|
| `data/originals/{space}/{doc}/文件名` | 用户上传的原文件 | 否 |
| `data/parses/{space}/{doc}/markdown.md` | MinerU 解析稿 | 否（进库用的是按页拆出的文本） |
| `data/parses/{space}/{doc}/structured_content.json` | 页 / 块 / bbox | 否，只给产品自己用 |

`data/` 已在 `.gitignore`。Markdown 上传不写 `data/parses`。

## 怎么人工验（BOT-2 对应）

1. 进入一个知识空间，上传一份 Markdown，列表先「处理中」，随后「已就绪」。
2. 上传 PDF 或 Word（本机 MinerU 8001 已开），同样流转到已就绪；`data/parses/.../structured_content.json` 存在。
3. 选 Excel，页面提示「只接受 PDF、Word、Markdown」，列表不新增。
4. 点「打开原文」：PDF 在浏览器里打开的是原 PDF，不是解析 Markdown。
5. 再建一个空间切过去，文档列表不是上一个空间的。
6. 失败样本（MinerU 关掉再传 PDF）：状态「失败」并有原因，该条不进检索。
