# 知识空间问答

企业内部桌面网页：已登录的人进入某个知识空间提问，系统用图谱加向量检索该空间的文档，回答带来源标注。

## 问题陈述

同事要查制度、方案或项目资料时，不知道文件在哪、该信哪一版。翻共享盘耗时长，问人又问不到维护者。若直接拿通用大模型来问，答案可能编造，也可能把其他部门的材料答进当前问题里。

知识要按部门或项目分开存放，并有一个地方能问一句就得到「只来自当前空间、并能点开原文核对」的回答。第一版先打通上传、建库和问答；成员名单和角色后加，但空间分桶从第一版就在。

## 解决方案

做一个只在桌面网页使用的企业内部问答系统。人用引导账号或被开通的账号登录，看到全部知识空间并进入其中一个。在当前空间开对话、提问、追问；系统只检索该空间内已就绪文档。有依据则回答并带来源标注（文件名 + 原文片段，可打开原文）；没有足够依据时展示「知识库中未找到」。

已登录即可创建知识空间、开通账号、上传 / 替换 / 删除 PDF、Word、Markdown。每个知识空间对应一个不可变的检索分桶。原文件留在内网，PDF 和 Word 在本机解析后再建库；建库抽取和问答命中的图谱、片段会发给已配置的云端模型。生成与 embedding 的地址和密钥用环境变量配置，第一版没有配置页。

## 用户故事

### 账号与进入

- **US-1** 作为已登录的人，我想要开通账号并设定用户名和密码，以便同事能够登录。
- **US-2** 作为持有账号的人，我想要用用户名和密码登录桌面网页，以便使用知识空间。
- **US-3** 作为未开通账号的人，我想要无法自助获得账号，以便知识不对无关的人开放。
- **US-4** 作为已登录的人，我想要退出登录，以便把工位交给别人使用。
- **US-5** 作为已登录的人，我想要看到全部知识空间并进入其中一个，以便在选定范围内提问。
- **US-6** 作为已登录但系统里还没有知识空间的人，我想要看到明确的空状态，以便知道该先建空间。
- **US-7** 作为已登录的人，我想要创建知识空间，以便部门或项目有自己的隔离单元。
- **US-8** 作为能看到多个知识空间的人，我想要切换当前知识空间，以便换到另一个隔离范围里提问和看文档。

### 文档

- **US-9** 作为已登录的人，我想要上传 PDF、Word 或 Markdown 到当前空间，以便问答有知识来源。
- **US-10** 作为已登录的人，我想要看到文档处于处理中、已就绪或失败，以便知道能不能拿它来问答。
- **US-11** 作为已登录的人，我想要替换一份文档，以便新的问答使用新内容。
- **US-12** 作为已登录的人，我想要删除一份文档，以便过时知识不再被答出来。
- **US-13** 作为已登录的人，当我上传不支持的文件类型时，我想要被明确拒绝，以便知道第一版只收 PDF、Word、Markdown。
- **US-14** 作为已登录的人，我想要看到当前空间的文档列表并打开原文，以便核对该答、自己翻原文。

### 问答与来源标注

- **US-15** 作为已登录的人，我想要在当前知识空间开一条新对话并提问，以便得到带来源标注的回答。
- **US-16** 作为已登录的人，我想要在同一条对话里追问，以便基于刚才的问题继续问。
- **US-17** 作为已登录的人，我想要看到我在本空间的对话列表并继续其中一条，以便过后再接着问。
- **US-18** 作为已登录的人，当当前空间没有足够依据时，我想要看到「知识库中未找到」，以便知道这次没有可用材料。
- **US-19** 作为已登录的人，当空间里还没有已就绪文档时提问，我想要看到「知识库中未找到」，以便空空间不会胡编一通看起来像有依据。
- **US-20** 作为已登录的人，我想要有依据的回答带来源标注（文件名和原文片段），以便不打开全文也能判断答到了哪。
- **US-21** 作为已登录的人，我想要从来源标注打开对应原文，以便核对答案是不是那一段。
- **US-22** 作为已登录的人，我想要提问时只使用当前知识空间的文档，即使我还看得到别的空间，以便不会串部门知识。
- **US-23** 作为已登录的人，当一份文档被删除后，我想要旧对话的回答文字还在，且对应来源标明「原文已删除」，以便历史问答不消失，但不再假装原文还在。
- **US-24** 作为已登录的人，当生成或 embedding 尚未配置时提问，我想要看到无法生成回答的明确提示，以便知道不是知识空间里没材料，而是系统还不能生成。

## 验收标准

### 账号与进入

- **AC-1** 系统里不存在自助注册入口；没有被开通的账号无法登录。〔覆盖 US-3〕
  - **怎么验**：组件测试确认登录页没有注册入口；后台测试用未开通的用户名请求登录被拒绝；真实页面 BOT-1 打开登录页确认没有注册。
- **AC-2** 已登录的人可以开通账号（用户名 + 密码）；该账号可以用这对凭证登录桌面网页。〔覆盖 US-1, US-2〕
  - **怎么验**：后台测试开通账号后登录成功、密码错误失败；真实页面 BOT-1 用开通的账号登录进入系统。
- **AC-3** 登录后列出系统中的全部知识空间；点入其中一个后，之后的文档和问答都针对该空间。〔覆盖 US-5, US-8〕
  - **怎么验**：后台测试空间列表含已创建的全部空间；真实页面 BOT-1、BOT-2 进入空间后文档列表与提问范围属于该空间。
- **AC-4** 系统里还没有知识空间时，登录后看到空状态，且没有文档列表和提问入口。〔覆盖 US-6〕
  - **怎么验**：后台测试空间列表为空；真实页面 BOT-1 看到空状态文案，没有提问输入框。
- **AC-5** 空状态里可以直接创建知识空间。〔覆盖 US-6, US-7〕
  - **怎么验**：真实页面 BOT-1 从空状态创建第一个知识空间后进入该空间。
- **AC-6** 已登录的人可以退出登录；退出后访问需要登录的页面会回到登录。〔覆盖 US-4〕
  - **怎么验**：真实页面 BOT-1 退出后再次打开原地址，回到登录页。
- **AC-7** 已登录的人可以创建知识空间；创建后该空间出现在所有已登录账号的列表里，并带有稳定的检索分桶名，之后不再改。〔覆盖 US-7〕
  - **怎么验**：后台测试创建后列表对另一账号可见，分桶名再次读取不变；真实页面 BOT-1 创建后左栏出现该空间。

### 文档

- **AC-8** 已登录的人可以在当前空间上传 PDF、Word、Markdown；上传后文档先为处理中，建库成功后变为已就绪，失败则标明失败且不进入检索。〔覆盖 US-9, US-10〕
  - **怎么验**：后台测试三种类型上传后状态流转，失败样本保持失败且检索不到；真实页面 BOT-2 上传一份 Markdown 直到已就绪。
- **AC-9** 上传不支持的文件类型被拒绝，提示只接受 PDF、Word、Markdown。〔覆盖 US-13〕
  - **怎么验**：后台测试上传 xlsx / pptx 被拒绝；真实页面 BOT-2 选 Excel 看到拒绝说明。
- **AC-10** 已登录的人可以看见当前空间文档列表并打开原文。〔覆盖 US-14〕
  - **怎么验**：后台测试读取原文成功；真实页面 BOT-2 打开原文。
- **AC-11** 已登录的人可以替换已就绪文档；替换完成后新的问答只使用新内容，不再使用旧内容。〔覆盖 US-11〕
  - **怎么验**：后台测试用桩检索断言替换后命中来自新内容；真实页面 BOT-5 替换后对新内容提问能答，对仅存在于旧内容的问题得到「知识库中未找到」。
- **AC-12** 已登录的人可以删除文档；删除后新的问答不再使用该文档。〔覆盖 US-12〕
  - **怎么验**：后台测试删除后检索不再命中；真实页面 BOT-5 删除后对仅该文档能答的问题得到「知识库中未找到」。

### 问答与来源标注

- **AC-13** 已登录的人可以在当前知识空间开新对话并提问，得到一条回答。〔覆盖 US-15〕
  - **怎么验**：后台测试在有命中时返回回答并写入该提问者的对话；真实页面 BOT-3 提问后看到回答。
- **AC-14** 同一对话可以追问；追问仍然只根据当前知识空间的文档作答。〔覆盖 US-16〕
  - **怎么验**：后台测试追问请求带上同一对话且检索范围仍是该空间；真实页面 BOT-3 追问后仍在同一条对话里看到新回答。
- **AC-15** 提问者能看到自己在当前知识空间的对话列表，并打开其中一条继续。其他知识空间的对话不出现在这个列表里。〔覆盖 US-17, US-8〕
  - **怎么验**：后台测试列表按提问者 + 当前空间过滤；真实页面 BOT-3 能从列表回到刚才的对话，切换空间后列表换成该空间的。
- **AC-16** 当前知识空间没有足够依据时（包括没有任何已就绪文档），回答文本为「知识库中未找到」。第一版不断言此时是否调用生成模型。〔覆盖 US-18, US-19〕
  - **怎么验**：后台测试在检索无命中和空空间时返回该句；真实页面 BOT-4 在空空间和无关问题上看到该句。
- **AC-17** 有足够依据时，回答带来源标注，每条来源含文件名和原文片段；点击来源可打开对应原文。〔覆盖 US-20, US-21〕
  - **怎么验**：后台测试有命中时回答附带来源文件名与片段；真实页面 BOT-3 点来源打开原文。
- **AC-18** 提问只检索当前知识空间的已就绪文档。提问者还能进入另一空间时，另一空间的文档不会出现在本次来源标注里，也不会用来生成回答。〔覆盖 US-22〕
  - **怎么验**：后台测试两空间各有一份互不相同的文档，在空间甲提问只命中甲；真实页面 BOT-4 验证来源不含另一空间的文件名。
- **AC-19** 文档被删除后，旧对话的回答文字仍在；该回答里指向已删文档的来源标注显示「原文已删除」，且不能再打开原文。〔覆盖 US-23〕
  - **怎么验**：后台测试删除后旧对话记录仍在、来源状态为已删除；真实页面 BOT-5 打开旧对话看到回答和「原文已删除」。
- **AC-20** 生成或 embedding 未配置时，提问界面提示无法生成回答，而不是「知识库中未找到」。〔覆盖 US-24〕
  - **怎么验**：后台测试未配置时提问不调用外部、返回明确的未配置错误；真实页面 BOT-4 未配置时看到无法生成的提示。

## 测试决策

### 接缝

接缝仍是产品 HTTP API，与上一版确认过的边界相同：不测切块算法，不断言向量距离，不测提示词原文，不测 MinerU 版面还原。LightRAG 的插入和查询、MinerU 解析，在后台测试里都换成桩。

1. **带桩检索引擎的 HTTP API（主接缝，后台测试）**  
   桌面网页只通过这一组接口工作。测试时替换 LightRAG 的插入与 mix 查询为桩，并替换 MinerU 解析为桩（给定 PDF/Word 返回固定 Markdown，不启动本机 MinerU）：有检索命中时返回可预测的回答文本和来源；空间隔离、文档状态、只搜当前空间、替换/删除对检索的影响，全部在这一层断言外部行为（请求进、响应出、持久化后的下一次请求）。第一版无命中时的展示文案在这一层断言返回值，不断言是否打到生成桩。不测 MinerU 版面还原质量，不测切块算法。

2. **真实桌面网页 BOT（最高接缝）**  
   对着跑起来的桌面网页操作，后端仍接同一套服务。只覆盖人眼必须看见的主路径：登录、建空间、上传、提问、来源打开原文、追问、切换空间、替换删除后的问答变化、模型未配置提示。

什么算好测试：只通过接口或页面观察行为；用固定文档夹具让检索命中可预测；不为了测 RAG 去断言某个向量库的内部距离分数。

## 实现决策

- 交付形态是桌面端网页，只通过一组我们自己的 HTTP API。第一版不做独立安装包、不做手机网页。
- 检索引擎是 LightRAG Core（查询 `mix`：图谱 + 向量），嵌在 FastAPI 进程里。不用 LightRAG Server / WebUI，不用 LlamaIndex。见 [ADR 0001](../adr/0001-lightrag-core.md)。
- 每个知识空间对应一个 LightRAG workspace，创建后不可变。提问只打当前空间。第一版凡登录即可进入全部知识空间、创建空间、开通账号、上传和提问，不做成员校验、不区分空间管理员。
- 身份是账号（用户名 + 密码）+ 服务端会话。启动时用环境变量写入引导账号。不能自助注册，不对接 SSO。
- 建库时 LightRAG 对切块抽取实体关系，因此切块会进入抽取模型；问答时实体、关系和命中片段进入生成模型。出网边界按此执行。
- 产品表和 LightRAG 的 KV、向量、图谱都用 PostgreSQL + pgvector。图谱用普通表（PGTableGraphStorage），不用 Apache AGE。见 [ADR 0002](../adr/0002-postgres-pgvector.md)。缺库就停，不用 SQLite 或其他库顶上。
- 原文件存本地目录。Word 按 `.docx` 接受。只接受 PDF、Word、Markdown。打开原文打开的是这份原文件，不是解析稿。
- **PDF、Word 的建库文本由本机 MinerU 4.x 解析成带标题和表格的 Markdown，再交给 LightRAG `ainsert`。** Markdown 上传跳过解析，原文即建库文本。见 [ADR 0003](../adr/0003-mineru-local-parse.md)。
- **禁止**用 `pypdf` / `python-docx` 抽文本（依赖里即使暂时还在也不调用，实现时从 `pyproject.toml` 删除）。**禁止** mineru.net 云解析和 OSS 预上传。
- MinerU 与产品进程分离：独立目录 `C:\code\RAG\MinerU`（自己的 uv 环境）跑 `mineru-kit api-server`，监听 **127.0.0.1:8001**（知识库 API 占用 8000）。产品 FastAPI **只 HTTP 调用**该地址，不把 `mineru` 装进本仓库 uv 环境，不在请求线程里同步跑解析。数字 PDF 用 `flash` + `ocr-mode txt`；扫描件再升 `standard`。国内权重走 ModelScope；企业环境关闭遥测。操作手册见 MinerU 目录 README。
- 建库时保住页定位：解析结果带 `page_idx`，插入 LightRAG 时 `file_path` 带页锚点（如 `制度.pdf#page=12`）。来源列表只展示检索返回的 chunks，不用模型自报的页码。点来源打开原文时尽量落到该页。
- 进入 LightRAG **之前**，表格与表题、脚注保持完整、不拆开。不替换 LightRAG 切块器。LLM 把表行写成自包含陈述第一版不做，表内问答仍差再加。
- 无足够依据时展示「知识库中未找到」：写进 mix 查询提示，或产品层发现没有有效 chunk 时直接返回该句。不搬竞赛式 number/boolean 答题卡，不做跨文档比较拆问。
- 生成与 embedding 都走 OpenAI 兼容接口，地址、密钥、模型名由环境变量配置。第一版不做配置页。
- 对话按「提问者 + 知识空间」持久化。第一版不做「仅自己可见」的强制校验（后加权限时再收紧）。
- 文档替换是覆盖，不保留历史版本。
- 测试接缝仍是我们的 HTTP API；LightRAG 的插入和查询、MinerU 解析，在后台测试里都换成桩。

### 开发批次

**批次 1：账号、登录与知识空间**

- Goal：引导账号登录、开通账号、创建/列出/进入知识空间；每个空间有稳定的 LightRAG workspace 名。
- 验收标准：AC-1, AC-2, AC-3, AC-4, AC-5, AC-6, AC-7
- 交接物：可登录的桌面网页；左栏知识空间列表。

**批次 2：文档上传与原文**

- Goal：在当前空间上传 PDF / Word / Markdown。PDF、Word 经本机 MinerU 转成 Markdown 再进 LightRAG；列表里能打开原文；不支持的类型被拒绝。不使用 pypdf / python-docx。
- 验收标准：AC-8, AC-9, AC-10
- 交接物：文档列表与原文；处理中 / 已就绪 / 失败。

**批次 3：对话问答与来源标注**

- Goal：当前空间内多轮对话；`mix` 查询只打该空间；来源只展示检索命中并可落到页；无依据固定为「知识库中未找到」。
- 验收标准：AC-13, AC-14, AC-15, AC-16, AC-17, AC-18, AC-20
- 交接物：四栏工作台里的问答。

**批次 4：文档变更**

- Goal：替换和删除后新问答走新图谱；旧对话保留「原文已删除」。
- 验收标准：AC-11, AC-12, AC-19
- 交接物：可演示的主路径。

## 不在范围内

- 对接飞书、钉钉、SharePoint 或其他外部知识源。
- 公司 SSO / LDAP / 组织架构同步。
- 手机网页或可安装客户端。
- PPT、Excel 或其他未列出的文件类型。旧版 `.doc` 不收。
- 文档历史版本、按版本提问。
- 审计后台。
- 自助注册。
- 跨知识空间一次检索。
- 成员权限、空间管理员、系统管理员上帝视角（后加；第一版凡登录可进全部空间）。
- 对话仅提问者可见的强制校验（后加）。
- 无命中则禁止调用生成模型（后加；第一版仍展示「知识库中未找到」，不断言此时不打模型）。
- 生成模型配置页（第一版只走环境变量）。
- LightRAG Server / WebUI 作为对外产品。
- LlamaIndex 再包一层。
- 回答质量的主观打分。
- 用 SQLite 或其他库临时代替 PostgreSQL + pgvector。
- mineru.net 云解析、把 PDF 预上传到 OSS。
- 用 pypdf / python-docx 抽取建库文本。
- 把 MinerU 装进产品 FastAPI 进程或本仓库 uv 环境。
- LLM 表格行级序列化（后加；第一版只保证表在 Markdown 里完整）。
- 竞赛式 typed 答案（number / boolean / names）和跨文档比较拆问。
