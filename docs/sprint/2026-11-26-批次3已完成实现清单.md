## 覆盖的验收

- **AC-13** 已登录的人可以在当前知识空间开新对话并提问，得到一条回答。
- **AC-14** 同一对话可以追问；追问仍然只根据当前知识空间的文档作答。
- **AC-15** 提问者能看到自己在当前知识空间的对话列表，并打开其中一条继续；切空间后列表换成那个空间的。
- **AC-16** 没有足够依据时（包括没有任何已就绪文档），回答文本为「知识库中未找到」。
- **AC-17** 有依据时回答带来源标注（文件名 + 原文片段）；点击来源打开原文件，带 `#page=n` 时尽量落到该页。
- **AC-18** 提问只检索当前空间；另一空间的文档不会出现在来源里，也不会用来生成。
- **AC-20** 生成或 embedding 未配置时提示「无法生成回答」，而不是「知识库中未找到」。

工作台四栏齐了：空间 / 对话列表 / 问答 / 文档。产品问答不打调试接口 `POST /api/rag/query`。

## 第 1 步：产品问答 API + 落库（先不动工作台）

1. 产品表补上 `conversations`、`messages`。对话按「提问者 + 知识空间」落库。第一版列表按这两维过滤；打开 / 追问不校验「只能看自己的」（spec 写明后加）。
2. 产品 HTTP 挂在当前空间下，`mix` 只用该空间的 `lightrag_workspace`，调用方不准再填 workspace。
3. 请求体 `{"question": "..."}`。首问截断成对话 `title`（最多 80 字）。
4. 生成 / embedding 未配置：503，文案 **「无法生成回答」**，不落库、不打 mix。
5. 没有已就绪文档：回答 **「知识库中未找到」**，来源空，不打 mix。
6. 有就绪文档但 mix 没有有效 chunk（正文非空）：同样这句。此时可能已经打过模型，第一版只保证展示文案。
7. 有命中：回答用检索返回的 chunks 做成来源，每条含 `filename`、`snippet`、`doc_id`、`page`。`page` 来自已有的 `split_page_anchor`，不用模型自报页码。`doc_id` 按当前空间文件名解析后写入，给批次 4「原文已删除」用。
8. 同一轮问、答若都用 Postgres 事务里的 `now()`，时间戳会撞上、顺序颠倒。写入时问比答早 1 毫秒；读取时同时刻先问后答。
9. 删空间时先清对话和消息，再删文档和空间。

主要代码：`api/app/models.py`、`api/app/services/conversations.py`、`api/app/repositories/conversations.py`、`api/app/routes/conversations.py`。表说明：`docs/refer/database-tables.md`。

## 第 2 步：中间栏提问 / 追问 / 点来源打开原文件

1. 无知识空间：不出现输入框，文案「先创建一个知识空间」。
2. 有空间：中间栏输入问题。第一次「提问」走 `POST .../conversations`；之后同一条里「追问」走 `POST .../conversations/{id}/messages`。
3. 切空间丢掉当前对话，避免追问打到另一个空间。
4. 「新对话」清空中间栏，下一次提问再开一条。
5. 未配置时界面展示接口返回的「无法生成回答」，不当成一条助手消息。
6. 来源展示文件名、页码（有则「第 n 页」）和原文片段。有 `doc_id` 的可点，走已有的 `openOriginal(spaceId, docId, page)`，同源打开原文件（不是解析稿），带 `#page=n` 时尽量落到该页。没有 `doc_id` 的只展示、不能点。
7. 第二栏对话列表这一步仍是占位，避免半成品列表。

主要代码：`web/src/pages/workbench/Chat.tsx`、`web/src/api/conversations.ts`。

## 第 3 步：对话列表

1. 第二栏「对话」只列 **当前账号 + 当前空间**；切空间后列表跟着换。
2. 点一条 `GET` 详情，中间栏打开该对话，可继续追问。
3. 新提问或追问成功后列表刷新（按 `updated_at` 降序），刚那条排在上面并保持选中。
4. 「新对话」清空中间栏选中态，列表仍在。
5. 切空间、删当前空间会清掉选中对话。
6. 无空间：「先创建一个知识空间」；有空间无对话：「还没有对话」。

主要代码：`web/src/pages/workbench/Conversations.tsx`、`web/src/pages/workbench/index.tsx`、`web/src/pages/workbench/Chat.tsx`。

## 接口（批次 3 产品用）

| 方法 | 路径 | 行为 |
|---|---|---|
| GET | `/api/spaces/{space_id}/conversations` | 当前账号在该空间的对话列表 |
| POST | `/api/spaces/{space_id}/conversations` | 开新对话并提问，返回整段对话 |
| GET | `/api/spaces/{space_id}/conversations/{id}` | 对话 + 消息 |
| POST | `/api/spaces/{space_id}/conversations/{id}/messages` | 追问，检索范围仍是该空间 |

列表项：`id`、`title`、`created_at`、`updated_at`。

详情另含 `messages[]`：`id`、`role`（`user` / `assistant`）、`content`、`sources`、`created_at`。

助手消息 `sources`：`filename`、`snippet`、`doc_id`、`page`。用户消息 `sources` 为空。

未配置：503，`{"detail": "无法生成回答"}`。

## 怎么人工验（BOT-3 / BOT-4 对应）

1. 当前空间有已就绪文档，提问后中间栏看到回答；来源含文件名和片段；点来源打开的是原文件，PDF 尽量落到页。
2. 同一条里追问，仍在该对话，检索范围仍是当前空间。
3. 离开后再从本空间对话列表打开这条；切到另一空间，列表不是刚才那些。
4. 空空间或无关问题：回答「知识库中未找到」。
5. 清空生成 / embedding 配置后再问：提示「无法生成回答」，不是「知识库中未找到」。
6. 两个空间各有一份互不相同的文档：在甲提问，来源不含乙的文件名。
