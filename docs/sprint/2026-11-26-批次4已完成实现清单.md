## 覆盖的验收

- **AC-11** 替换已就绪文档后，新问答只用新内容，不再用旧内容。不保留历史版本。
- **AC-12** 删除文档后，新问答不再命中该文档。
- **AC-19** 文档删除后，旧对话的回答文字仍在；来源显示「原文已删除」，不能打开原文。

删空间时 PostgreSQL 里该 LightRAG workspace 的图谱 / 向量 / 块一并清空。建库质量（表 + 表题成组）不在本批。

---

## 第 1 步：LightRAG 原语

1. 产品 `documents.id` 不是 LightRAG `doc_id`。Markdown 一行 `file_path=文件名`，PDF/Word 每页一行 `文件名#page=n`。
2. `delete_by_filename`：分页扫 `doc_status`，用已有 `split_page_anchor` 对齐文件名，串行 `adelete_by_doc_id`。
3. `drop_workspace`：对齐 LightRAG Server `/documents/clear`，对各 storage `drop()` / 向量 `drop_all_models()`。Postgres 是 `DELETE WHERE workspace=`，不是 DROP TABLE。
4. 关掉问答 LLM 缓存（`enable_llm_cache=False`）。缓存按问题键，图谱清掉后仍会把旧回答再答出来。抽取缓存仍开。

主要代码：`api/app/lightrag/engine.py`。

---

## 第 2 步：删除接通图谱

1. 空间里有 `processing` 文档时，拒绝删除 / 替换 / 删空间，409「文档正在建库」。避免建库和删除抢同一条 LightRAG pipeline。
2. 删文档：先按文件名清图谱，再删产品行和磁盘。图谱失败则不删产品行。
3. 删空间：先 `drop_workspace`，再清对话 / 文档 / 空间 / 磁盘，最后 `forget_workspace`。
4. 删空间时消息必须先于对话用 SQL 删掉；ORM 逐条 `delete` 会在 autoflush 时先删对话，撞外键。

主要代码：`api/app/services/documents.py`、`api/app/services/spaces.py`、`api/app/repositories/conversations.py`。

---

## 第 3 步：替换

1. `PUT /api/spaces/{space_id}/documents/{doc_id}`，multipart 字段名 `file`，同一 `documents.id` 覆盖。
2. 校验与上传同一套。同一空间文件名唯一（替换自己除外），409「该空间已有同名文档」。
3. 先写新原文件，再按旧文件名清图谱，清解析稿，必要时删掉旧文件名；该行改为 `processing` 后走现有 `ingest.schedule`。
4. `stored_path` 随替换更新。
5. 文档栏已就绪 / 失败可「替换」；处理中禁用替换和删除。

主要代码：`api/app/services/documents.py`、`api/app/routes/documents.py`、`web/src/pages/workbench/Documents.tsx`。

---

## 第 4 步：旧对话「原文已删除」

1. 不改 `messages.sources` JSONB。读对话（详情 / 首问 / 追问）按当前空间仍在的 `documents.id` hydrate `deleted`。
2. 有 `doc_id` 且文档行没了 → `deleted=true`，界面「原文已删除」，不能点。`doc_id` 本来就是空的只展示，不是已删除。
3. 文档删除或替换成功后刷新当前对话。

主要代码：`api/app/routes/conversations.py`、`web/src/pages/workbench/Chat.tsx`。

## 接口（批次 4 新增 / 行为变化）

| 方法 | 路径 | 行为 |
|---|---|---|
| PUT | `/api/spaces/{space_id}/documents/{doc_id}` | 覆盖原文件并重建库，返回 `processing` |
| DELETE | `/api/spaces/{space_id}/documents/{doc_id}` | 先清 LightRAG，再删产品行和磁盘 |
| DELETE | `/api/spaces/{space_id}` | 先清空该 workspace 的图谱行，再删产品数据 |

助手来源现含 `deleted`。处理中变更返回 409「文档正在建库」。同名上传 / 替换别人的名字返回 409「该空间已有同名文档」。

## 怎么人工验（BOT-5 对应）

需要先重启产品 API（加载本批代码），工作台 `localhost:5173`。

1. 当前空间有已就绪文档，提问得到带来源的回答。
2. 点「替换」换成完全不同的内容，等到已就绪。对新内容提问能答；对只存在于旧内容的问题，回答不应再引用旧文件名。
3. 删除该文档，打开第 1 步那条旧对话：回答文字还在，来源「原文已删除」，不能打开。
4. 再问只靠那份文档才能答的问题，得到「知识库中未找到」。
5. 删空间后，该空间从左栏消失。
