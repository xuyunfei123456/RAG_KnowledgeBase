## 覆盖的验收

- **AC-1** 没有自助注册入口；未被开通的账号无法登录。
- **AC-2** 已登录的人可以开通账号（用户名 + 密码）；该账号可以用这对凭证登录。
- **AC-3** 登录后列出系统中的全部知识空间；点入其中一个后，之后的文档和问答都针对该空间。
- **AC-4** 系统里还没有知识空间时，登录后看到空状态，没有文档列表和提问入口。
- **AC-5** 空状态里可以直接创建知识空间。
- **AC-6** 已登录的人可以退出；退出后再访问需要登录的页面会回到登录。
- **AC-7** 创建知识空间后，该空间出现在所有已登录账号的列表里，并带有稳定的检索分桶名 `lightrag_workspace`，之后不再改。

交接物：可登录的桌面网页（`localhost:5173`）；左栏知识空间列表。第一版凡登录即可进入全部空间、创建空间、开通账号，不做成员校验、不区分空间管理员。

## 第 1 步：进程骨架与会话

1. 产品 HTTP 是 FastAPI（`api/app/main.py` 只装配）。前端 Vite + React，开发时 `5173`，`/api` 代理到 `127.0.0.1:8000`。
2. 身份是账号 + 服务端会话：Starlette `SessionMiddleware`，cookie `SameSite=Lax`，登录成功把 `account_id` 写入 session。前端请求一律 `credentials: "include"`。
3. 需要登录的接口走 `current_account`：没有 session 或账号已删，返回 401「未登录」。
4. PostgreSQL + pgvector，缺库就停，不用 SQLite 顶上。启动时 `CREATE EXTENSION IF NOT EXISTS vector`，再按 SQLAlchemy 模型建产品表。
5. 生成 / embedding 地址和密钥只从环境变量读，第一版没有配置页。

主要代码：`api/app/main.py`、`api/app/security.py`、`api/app/db.py`、`api/app/config.py`、`web/vite.config.ts`、`web/src/api/client.ts`。

## 第 2 步：引导账号、登录、退出

1. 进程启动若库里没有引导账号，用 `.env` 的 `BOOTSTRAP_USERNAME` / `BOOTSTRAP_PASSWORD` 写入一条（默认 `admin` / `admin123`）。不能自助注册，不对接 SSO。
2. `POST /api/auth/login`：用户名或密码不对，统一 401「用户名或密码错误」，不区分账号不存在还是密码错。
3. 密码存 `PBKDF2-HMAC-SHA256`（盐 + 摘要），校验用 `hmac.compare_digest`。
4. `POST /api/auth/logout` 清空 session。
5. `GET /api/auth/me` 用来刷新页面后恢复登录态。前端 `App` 先打 `/me`：未登录出登录页，已登录进工作台。
6. 登录页只有用户名、密码和「登录」，文案写明「没有注册。账号由引导账号开通。」没有注册按钮或注册路由。

主要代码：`api/app/services/accounts.py`、`api/app/services/startup.py`、`api/app/routes/auth.py`、`web/src/pages/Login.tsx`、`web/src/App.tsx`。

## 第 3 步：开通账号

1. 必须先登录。工作台顶栏「开通账号」打开抽屉，提交 `POST /api/accounts`。
2. 用户名 2～64 字，密码 6～128 字。用户名已存在返回 409「用户名已存在」。
3. 开通后可用这对凭证从登录页进入。未开通的用户名登录失败（AC-1）。
4. 「开通」按钮开通中显示「开通中」并禁用，避免连点。

主要代码：`api/app/routes/auth.py`、`web/src/pages/workbench/AccountDrawer.tsx`、`web/src/api/auth.ts`。

---

## 第 4 步：知识空间（创建 / 列出 / 进入）

1. 产品表 `knowledge_spaces`：`id`、`name`、`lightrag_workspace`、`created_at`。
2. 创建时 `lightrag_workspace = "ws_" + 32 位 hex`，库内唯一。写入后接口和后台都不再改这个字段（AC-7）。
3. `GET /api/spaces` 列出系统中**全部**空间（第一版不做成员过滤），按创建时间。
4. `POST /api/spaces` 创建，名称 1～128 字。创建后出现在所有已登录账号的列表里。
5. 左栏点某个空间，设为当前空间；之后文档和问答都带这个 `space_id`，检索只用该行的 `lightrag_workspace`。
6. 没有空间：左栏「还没有知识空间」，中间栏不出现提问框，文档栏「先创建一个知识空间」（AC-4）。空状态同一栏就能填名称创建（AC-5）。
7. 创建后左栏出现该空间并自动进入。切到另一个空间后，文档列表和对话列表换成那个空间的。

主要代码：`api/app/models.py` 的 `KnowledgeSpace`、`api/app/repositories/spaces.py`、`api/app/routes/spaces.py`、`web/src/pages/workbench/Spaces.tsx`、`web/src/pages/workbench/index.tsx`。

## 接口（批次 1 产品用）

| 方法 | 路径 | 行为 |
|---|---|---|
| POST | `/api/auth/login` | 登录，写入 session |
| POST | `/api/auth/logout` | 退出，清空 session |
| GET | `/api/auth/me` | 当前账号；未登录 401 |
| POST | `/api/accounts` | 已登录的人开通账号 |
| GET | `/api/spaces` | 全部知识空间 |
| POST | `/api/spaces` | 创建空间，返回含不可变 `lightrag_workspace` |

账号字段：`id`、`username`。空间字段：`id`、`name`、`lightrag_workspace`。

## 怎么人工验（BOT-1 对应）

1. 打开桌面网页，登录页没有注册入口。
2. 用未开通的用户名登录，失败。
3. 用引导账号登录：若还没有空间，看到空状态，没有提问输入框。
4. 创建一个知识空间（例如「制度」），左栏出现并进入该空间。
5. 开通账号 A。退出。再打开刚才的地址，回到登录页。
6. 用账号 A 登录，左栏能看到「制度」，`lightrag_workspace` 与创建时一致、不会变。
